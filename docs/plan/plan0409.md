# UI框架与组件设计相关需求
1. 去除所有tailwindcss依赖，不使用css库
2. 使用bits-ui作为无头UI库，我将重头对该项目的样式进行设计
   - https://bits-ui.com/docs/llms 阅读该docs，获取llms.txt作为设计bits ui相关内容时的基准指南，写入到agents.md
3. 将自定义组件放置到统一文件夹/子文件夹结构中统一管理
4. 本项目会被设计成Pixel Art的UI美术风格，因此，fontsize margin padding gap等尺寸会使用px作为单位，用户可以直接使用浏览器缩放进行缩放操作

# 响应式设计相关
1. 当media width小于720px时，直接用黑色填满屏幕，说明该应用最小分辨率宽度应大于720p
2. 不要过度设计响应式设计，不要考虑竖屏行为，写入agents.md：**该应用是纯横屏应用，不要过度设计响应式设计**

# 界面文案包装设计
1. 当前设计阶段**只设计英文**，写入到agents.md中

# tools界面架构设计要求
1. tools的最顶层界面组件结构被严格限制（程序设计层面必须体现，需要有完整的schema和doc指南），所有下列的组件都由外部的“总管系统”负责设计，tools只能负责调用。以下会梳理为tools设计的组件结构：
   1. `<LeftPanel /> <RightPanel />` 必须项：
      - LeftPanel
        -  用于放置该tools的所有参数设置或信息显示等数据相关内容，flex column gap 8px
           -  `<MainInfo />` 放在LeftPanel最顶端，放置工具的title,desc,右侧有常驻按钮，点击显示菜单，上方按钮可由工具定义，divider后最下方有“About”按钮，点击显示metadata信息
           -  `<Section />` 最大的一个分级组件，主要用于定义统一的background and outline，以及排版行为
              -  后续的内容可以使用通用样式自行设计
   2. `<RightPanel />` 放置一个Canvas or sth，用于预览该工具的效果
      - 需要有缩放画布功能 

# 所有子工具需要依靠的技术栈：
- 所有技术栈都是前端技术栈，因为是Github Pages网页，无后端计算支持
- 单纯计算简单数值：直接原生js
- 快速排版功能：svelte+css
- 3D相关图形效果生成：three.js
- 2D相关图形效果生成：niri.js
- 这些功能都需要在框架内定义好并允许各个tools按需调用
  - 因此需要考虑相关技术细节，包括：
    - tools调用框架中这些技术栈的协议
    - tools是否需要事先注册这些技术栈以实现按需加载，提高性能
    - 等等
