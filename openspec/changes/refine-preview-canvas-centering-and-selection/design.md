## Context

当前 PreviewCanvas 使用网格容器加 place-items 居中，但在内容尺寸远大于视口时，内容布局盒会从左上内边距起点放置，再进入 transform 缩放流程。结果是内容几何中心与视口中心长期不重合，用户在 Fit、1:1 与手动缩放之间切换时会感知到“锚点偏向右下”的视觉漂移。

同时，PreviewCanvas 作为框架级通用交互层，当前未统一约束文本选择行为。拖拽平移与滚轮缩放时容易触发文本误选高亮，影响导航交互连续性。

## Goals / Non-Goals

**Goals:**
- 将 PreviewCanvas 内容定位基线改为“先中心定位，再执行缩放/平移”，使大尺寸内容与小尺寸内容使用同一几何锚点。
- 保持现有缩放模型、工具栏操作与 pan 状态语义不变，仅修复锚点与布局参考系。
- 在框架层默认禁止 PreviewCanvas 内容区文本选择，避免拖拽/缩放过程误选。
- 以最小外部 API 变更完成修复，不要求工具侧新增配置。

**Non-Goals:**
- 不重构 PreviewCanvas 的 zoom 计算模型（logical zoom、renderScale 与 DPR 逻辑保持不变）。
- 不新增新的右侧容器类型，也不改变 FullStage 职责边界。
- 不为工具新增“可选文本白名单”配置接口（若个别工具确有需求，后续单独提案）。

## Decisions

### Decision 1: 采用中心锚点布局（C 方案）替代网格隐式轨道居中
PreviewCanvas 将把内容容器切换到显式中心锚点模型：由视口中心点确定内容参考位置，再叠加 pan 与缩放变换，避免大内容在布局阶段先贴左上导致的错位。

备选方案与取舍：
- 方案 A（继续 grid，仅补 place-content）: 改动最小，但仍依赖超大内容下的轨道行为，长期可预期性不足。
- 方案 B（改 flex 居中）: 行为更直观，但在超大固定尺寸元素与复合 transform 叠加时仍存在实现细节歧义。
- 方案 C（中心锚点）: 参考系最稳定，和 pan/zoom 的几何含义最清晰，适合共享壳层长期维护。

### Decision 2: 缩放与平移继续由 PreviewCanvas 统一管理，保留现有状态机
保留 mode、manualZoom、fitZoom、panX、panY 的状态结构，改动集中在内容定位与 transform 组合方式，避免对现有交互逻辑产生额外回归面。

备选方案与取舍：
- 重写整套平移与缩放状态：风险高、收益低。
- 仅修正定位与变换表达：满足问题目标且改动边界可控。

### Decision 3: 在框架层默认禁用 PreviewCanvas 内容文本选择
PreviewCanvas 内容区将默认应用不可选策略，覆盖拖拽和滚轮导航常见路径，保证“预览导航优先于文本选择”的一致体验。

备选方案与取舍：
- 仅在拖拽开始时临时禁用选择：实现复杂且边界条件多。
- 仅在工具侧逐个处理：会造成重复补丁与行为不一致。
- 框架层默认禁用：实现直接、行为统一，符合共享壳层定位。

## Risks / Trade-offs

- [部分工具可能依赖可选文本] → Mitigation: 在文档中明确该默认行为，并允许工具通过更高优先级样式按需覆盖。
- [中心锚点改造导致 pan 体感变化] → Mitigation: 保持 pan 数值语义不变，并在 Fit、1:1、手动缩放三种模式下回归验证。
- [变换链调整引入边界裁切回归] → Mitigation: 覆盖大尺寸与小尺寸内容两类场景，验证内容边界与视口中心重合关系。

## Migration Plan

1. 更新 OpenSpec delta specs，明确 PreviewCanvas 的中心定位与不可选文本要求。
2. 在 PreviewCanvas 组件中实现中心锚点布局，并调整 transform 组合。
3. 在 PreviewCanvas 内容层添加框架级 user-select 限制。
4. 以 Aspect Ratio（大尺寸内容）与 Noise Texture（常规尺寸内容）进行对照验证。
