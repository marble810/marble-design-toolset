## Why

当前框架已经统一了工具壳层、技术栈加载与导出运行时，但尚未提供统一的文件输入能力。后续工具会把图像、影片与文字文件作为数据来源；如果继续由各个 tool 各自处理文件选择、类型校验、异步读取、预览资源释放与错误状态，会快速形成重复实现和不一致行为。

现在补上统一文件输入管道，可以在工具数量继续增加之前先收敛浏览器文件 API 的使用方式，给后续 tool 提供稳定、可复用、可测试的数据入口。

## What Changes

- 新增一个 framework-owned 的文件输入管道运行时，用统一接口接收图像、影片、文字三类文件并输出标准化结果。
- 为文件输入定义共享的类型、状态与错误语义，包括文件类型识别、读取结果、元信息提取、失败反馈与资源清理责任。
- 支持工具按需声明允许的输入类别与接收策略，避免每个 tool 重复拼装 `input[type=file]`、拖放数据解析与文件读取逻辑。
- 补充与该能力对应的规范、设计说明和实施任务，使后续工具可以在统一约束下接入文件输入。

## Capabilities

### New Capabilities
- `file-input-pipeline`: 定义工具接入统一文件输入运行时的方式，以及图像、影片、文字三类输入在校验、读取、标准化结果与错误处理上的框架级契约。

### Modified Capabilities
无。

## Impact

- 受影响代码主要位于 `src/lib/runtime/` 与 `src/lib/types/`，需要新增面向工具复用的文件输入模块与类型定义。
- 后续需要同步更新开发文档、Copilot skills 参考说明与 `AGENTS.md`，把统一文件输入管道纳入工具开发约束与阅读路径。
- 该能力优先基于浏览器原生文件 API 实现，不要求把新的重型依赖耦合进通用壳层。
