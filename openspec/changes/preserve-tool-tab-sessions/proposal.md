## Why

当前工作区虽然已经有标签栏、URL hash 同步和本地持久化，但标签页仍然只是在切换 `activeToolId`，实际渲染层始终只有一个活动工具实例。用户一旦切到别的标签页，原工具组件就会被卸载并在切回时重新加载，导致参数、预览导航和运行时上下文都回到初始状态，这与用户对“tab”的基本预期不一致。

同时，工作区已经具备恢复 `openToolIds` 与 `activeToolId` 的本地持久化基础，因此现在需要把“看起来像 tab 的切换器”提升为“真正的工作区会话模型”：切换标签页时保留实例，只有关闭标签页时才销毁；刷新后恢复上次打开的标签集合；首次访问且无 hash、无本地状态时保持空工作区。

## What Changes

- 将工作区标签行为从“单活动组件切换”调整为“多已打开工具会话并存，活动标签仅决定可见会话”。
- 要求已打开工具在标签切换时保持已挂载状态，只有用户点击关闭按钮时才真正销毁对应工具实例。
- 保留并明确现有本地持久化语义：恢复上次打开的标签集合和活动标签；首次访问且无有效 hash 与无本地状态时不自动打开任何工具。
- 保留有效 URL hash 的深链能力；当存在有效 hash 时，它仍然可以在初始进入时激活对应工具。
- 为工具运行时补充“活动/隐藏”生命周期语义，使隐藏标签中的重型预览或动画型工具能够暂停后台工作，并在重新激活时恢复。

## Capabilities

### New Capabilities
- `tool-session-lifecycle`: 定义工具标签会话的保活、关闭销毁以及活动/隐藏生命周期信号。

### Modified Capabilities
- `tool-shell-workspace`: 标签管理从活动组件切换升级为保活会话模型，并明确首次访问空工作区与 hash 深链并存的恢复规则。
- `tool-module-runtime`: 工具运行时需要支持可选的活动/隐藏生命周期消费方式，以便工具在保活标签模式下管理后台资源。

## Impact

- 受影响代码主要位于工作区壳层与运行时装配层，包括 `src/routes/+page.svelte`、workspace state 持久化模块、tool shell context、以及新的工具会话/可见性运行时。
- 受影响能力包括标签会话恢复、工具加载与销毁时机、About / MainInfo / Export Section 的活动工具来源，以及重型技术栈工具的后台资源管理方式。
- 需要新增或修改相应 OpenSpec artifacts，覆盖工作区标签语义、工具会话生命周期，以及实现与验证任务拆分。
